# 胜利场景评估与 90 天计划（dataalchemy + sympraxis）

> 2026-09 与带教对齐形成。本文是 dataalchemy/sympraxis 变现路径的执行依据；
> riskdeck 视角的设计另见 `docs/design/risk-view-design.md`，概念模型见 `docs/CONCEPTS.md`。

---

## 1. 战略对齐摘要（带教会话结论）

| 维度 | 结论 |
|---|---|
| 作用对象排序 | ② 职业与收入结构 > ④ 认知系统升级 > ① riskdeck 事业；投资理财不入圈 |
| 终局画像 | **主业保底现金流 + 副业产品资产**（混合双轨） |
| 时间燃料率 | 10～20 小时/周（真实值）；纪律：每周必须产出"可被他人看见的增量" |
| 载具 | **dataalchemy（NL 驱动的数据工作台）+ sympraxis/agentmemory（可验证工作流经验记忆）**= 一体两面；riskdeck = 个人项目驾驶舱（内部工具，停止投入，仅作布道样板间） |
| 目标用户 | **有强烈 AI 转型诉求 + 大量结构化数据待处理的企业** |
| 分发通道 | **主业即战场**（白天即目标客户现场；内部孵化 → 案例外溢） |

**本质判断**：瓶颈不是产品（引擎工程质量已达标），是**信任资产**（可验证的交付案例）。约束方程：10～20h/周 × 0 分发资产 × 企业级产品 ⇒ 唯一可行解 = **借主业场景锻造产品，把过程沉淀为案例**。

## 2. 候选胜利场景评分（临床数据域）

评分标准：痛点高频 / 三周可见效 / 可脱敏 / 有具体的人在乎。

| 场景 | 高频 | 三周 | 脱敏 | 有人在乎 | 判定 |
|---|---|---|---|---|---|
| **S1 病人数据异常告警** | ●●● | ●●● | ●●● | ●●●（数据管理员） | **首发** |
| **S3 锁库数据分析** | ●●（低频高戏剧性） | ●● | ●● | ●●●（PM/统计师） | **第二（演示王牌）** |
| **S4 TFL 报告生成** | ●●● | ●（全量=数月+CSV） | ●●●（CDISC 公开试点数据） | ●●●（统计编程组） | **切片进入** |
| **S2 中期分析** | ● | ✗（SAP 治理/监管） | ● | ●● | **排除出 90 天弧**（路线图远期） |

### 场景拆解

- **S1 首发胜利形态**：接入研究数据 → 每日自动产出异常清单（超范围/跨访视不一致/BLQ 未处置）→ 处置建议来自经验链召回 → 人工确认后入链。资产匹配：`sympraxis/packs/clinical_pk` 已有 `clinical.lab` 分支、BLQ 处置规则、单位 harmonize 算子模板。
- **S3 演示王牌**：锁库 = 清单驱动核查 + 全闭环才准锁 = **经验记忆完美用例**。演示叙事：*"新研究接库的第一天，系统就知道上一个研究锁库踩过的所有坑。"* 数据不必真实——**用历史锁库复盘**做场景，不等下一次真锁库。
- **S4 切片**：仅做"单一 Listing 的 NL 起草 + 与历史已验证输出交叉核对 + 差异解释"，定位**统计编程员的草稿机/核对器**；绝不做提交物生产路径的全量生成。数据源用 CDISC 公开 SDTM/ADaM 试点数据集（解决合法数据问题）。
- **S2 排除理由**：决策链在生物统计与监管事务，受 SAP 治理；三周不可见效，且做错是职业信用事故。数据管线成熟一年后再评估。

## 3. 合规与 IP 红线（先于一切执行）

1. **定位纪律**：所有内部演示把产品表述为**"辅助核对层/效率层"**，绝不说"替代已验证系统"——避免触发 CSV / 21 CFR Part 11 验证流程（`packs/clinical_pk/compliance/gxp_reserved.yaml` 已决策"先内部探索，架构预留 GxP"，维持该定位）。
2. **IP 纪律**：个人设备 + 个人时间开发；不搬运公司代码与数据；只搬运**脱敏的方法论与模式**；自查劳动合同发明/竞业条款；变现规模化前与雇主书面确认。
3. **数据纪律**：内部场景用脱敏数据；对外演示用 CDISC 公开试点数据或合成数据。

## 4. 90 天弧（10～20h/周）

**Phase 0 · 边界与选场（第 1～2 周，约 10h）**
- [ ] 自查雇佣协议发明/竞业条款
- [ ] 选定胜利场景（当前=S1），四条标准打分并存档
- [ ] 定义量化胜利指标（例：异常发现→处置闭环时长从 N 天 → N 小时；核查覆盖率；漏报率）

**Phase 1 · 内部交付（第 3～8 周）**
- [ ] S1 告警流水线跑通（NL 建规则 → 异常清单 → 经验召回建议 → 人工确认入链）
- [ ] 仅补"被场景逼出来的"生产缺口（大概率是**生产鉴权**，见 §6）
- [ ] 每周一个可被看见的增量；周日晚 30 分钟对账（红灯=本周无可视增量）

**Phase 2 · 资产化（第 9～13 周）**
- [ ] 对内：复盘 + 部门布道 → 换第二个场景（复利启动标志：场景来找你）
- [ ] 对外：一篇脱敏案例文（架构叙事，不提公司名）
- [ ] 开源最小引擎：`sympraxis` 的 `chainmatch` 纯库（零存储依赖，开源友好）；产品与域包留给企业版

**备选**：咨询先行——仅接受**一个**高价新单（定价 ≥ 主业时薪 3 倍），交付换案例，不可持续接。

## 5. 反事实对照（决策依据存档）

- 路径 X「闭门打磨 12 个月再对外」→ 无案例/无用户/无分发 + agent 记忆赛道默认化风险上升；资产净变化 ≈ 0。**否决。**
- 路径 Y「借主业场景锻造」→ 1～3 个可量化案例 + 生产缺口被真实需求倒逼补齐 + 内部口碑外溢通道。**采纳。**

## 6. 生产鉴权缺口（技术备忘）

现状（`sympraxis/src/agentmemory/auth.py`）：`local-dev` 匿名管理员主体 + 本地 HMAC 自签自验令牌——信任锚是服务自身，仅适合单人本地。
生产要求：宿主系统（dataalchemy）对接企业 SSO 签发 JWT 断言 → agentmemory 经 **JWKS** 非对称验签（`iss/aud/exp` + 密钥轮换）→ claims 映射 `Principal`。
工作量校准：数天级（OIDC 发现/JWKS 缓存轮换、claims 映射、mock IdP 集成测试）。
**时机**：内部场景出现第二个真实使用者/部门时立即提升为最高优先级（安全评审第一问）；此前不预建。
