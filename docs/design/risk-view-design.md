# 风险视图设计规范（v2，含三变体原型）

> 2026-09 与需求方对齐。本文是 riskdeck「风险」一级视图的落地依据。
> 交互原型：`viewer/prototype-risk-view.html`（双击打开；`?variant=A|B|C` 直达；←/→ 切换）。
> 术语与数据模型：见 `docs/CONCEPTS.md`（概念 v2）；参照样图：`docs/research/`。

---

## 1. 设计目标（验收标准）

1. **宏观→微观多精度观察**：项目群 → 项目 → 一级任务 的层级可展开；
2. **折叠保留统计**：宏观态折叠微观事项时，行/卡上仍显示内部统计的**简化表征**（chips、热力条、sparkline、达成度环）；
3. **风险醒目**：风险四类有统一色标，危急项有脉冲级警示；风险是一级导航视图，直接进入；
4. **多项目宏观 + 项目内风险统计**：一屏多项目，每行携带项目内风险统计；
5. **可下钻**：项目/模块（任务）级风险视图可达（Peek/面板/抽屉）；
6. **阶段性汇报窗口**：宏观视图体现**可输入时间段**内 event 状态变化（窗口全局生效）。

## 2. 全局共享元素（三个变体共用）

### 2.1 阶段汇报窗口（全局控件）
- 位置：顶部说明栏右侧；控件：`7 天 | 14 天 | 30 天 | 90 天` + 自定义天数输入（回车生效）。
- 作用域：全局——切换后重渲染当前变体，所有"阶段变化"统计、KPI、窗口高亮同步刷新。
- 窗口内事件类型（对应事件流）：`risk.open` 登记 / `risk.close` 解除 / `task.move` 任务状态迁移 / `gate` 门禁通过/未过 / `ms.slip` 里程碑滑动 / `decomp` 拆解产出 / `fte` 资源投入变化。

### 2.2 顶层 KPI 条
危急风险（脉冲点）/ 高风险 / 目标未达标（另计未评估）/ 里程碑预警 / 已错过 / **窗口内事件** / 升级中·需决策。
（变体 C 用窗口侧 KPI 替代存量 KPI，见 §3.3。）

### 2.3 风险四类色标（全局 token）
| 类别 | token | 语义 |
|---|---|---|
| 进度 | `--cat-prog`（琥珀） | 预测晚于 FTE 契约 |
| 资源 | `--cat-res`（紫） | 刚需资源缺口（人/硬件/账号） |
| 关键问题 | `--cat-prob`（红，最高警示级） | 无解决方案（含业界无解） |
| 质量 | `--cat-qual`（蓝） | 已实现但过不了评价门禁 |

### 2.4 微件词汇表
- **目标达成度环**：conic-gradient 圆环 + 中心百分比；颜色=达标(绿)/临界(琥珀)/未达标(红)/未评估(灰)；tooltip=状态+百分比。
- **门禁标签**：`✓通过 / ✗未过 / —未评估`。
- **里程碑集合 chip**：`名称 成员完成/总数 ◆状态`；四态（planned/at-risk/hit/missed）由成员任务推导（见 CONCEPTS §3）。
- **里程碑轨道**：迷你时间轴，菱形按契约日落位（四态着色，at-risk 带光晕），今天线贯穿。
- **拆解徽章**：`已拆解 n`（紫）/ `⚠ 未拆解`（虚线灰，警示——拆解缺失即管理风险信号）。
- **契约/预测漂移 chip**：`契约 MM-DD` + `⏱ +Nd`（红，预测晚于契约）/ `⏱ 按期`（绿）/ `预测 —`（预测缺失本身是进度风险输入）。
- **风险 5×5 严重度章**：`p×i`，crit(≥15)/high(≥9)/med(≥5)/low。
- **sparkline**：12 周序列微折线；**趋势箭头**：近 4 周 vs 前 4 周（↑活跃/→平/↓回落）。
- **事件流行**：类型色点 + `n 天前` + `[类型] 文案`。

## 3. 三变体规范（结构互斥，可混搭）

### 3.1 变体 A · 驾驶舱泳道（推荐默认首页）
- **行 = 项目**：名称区（编码/一级任务数/契约滑动数）+ 目标环组 + 里程碑轨道与集合 chips + 四类风险 chips + **阶段变化 chips**（`风险 +n −m · 迁移 k · 滑动 s · 门禁 x✓/y✗ · 拆解 · FTE`）+ 12 周事件 sparkline + 趋势。
- **展开 = 一级任务**：任务目标达成度条、拆解徽章、契约/预测 chips、子任务进度、关联风险计数。
- **下钻 = Peek 侧滑**：任务目标卡（完成判定 + FTE 契约 + 拆解状态）→ 关联风险（严重度章 + 负责人 + 状态 + sparkline）→ 项目目标上下文 → 窗口内事件流。
- 定位：信息密度最全，适合日常驾驶。

### 3.2 变体 B · 风险矩阵气泡（高层一屏）
- **主面**：5×5 概率×影响热力矩阵（角标=落格风险数）；**气泡 = 项目**（位置=开放风险加权 p×i 均值、大小=暴露值、主色=最重风险类别、环内微格=四类构成）。
- **右栏**：阶段变化盒（窗口）→ 四类风险分布条 → 全组合 Top 风险排行。
- **下钻 = 侧滑**：项目目标卡组 → 里程碑集合 → 四类构成 → 依赖传播（真实系统由依赖边表推导）→ 窗口事件流。
- 定位：向管理层汇报的"一张图"。

### 3.3 变体 C · 时间泳道热力（阶段性叙事）
- **行 = 项目（可展开一级任务）**，**列 = 12 周**；格色深浅=**当周事件数**（蓝系），未来周虚线占位；窗口覆盖列描边高亮；今天线贯穿。
- 里程碑菱形按契约日落位（tooltip 显示成员完成比）；行尾摘要：风险 chips + 窗口事件数 + 趋势 + sparkline。
- **下钻 = 底部抽屉**：该周事件流水（按项目/任务过滤）。
- KPI 条改为窗口侧：窗口事件 / +登记 / −解除 / 滑动 / 危急存量。
- 定位：最贴合"阶段性汇报=一段时间内 event 状态变化"的叙事。

## 4. 数据映射（视图元素 ← 概念 v2 字段）

| 视图元素 | 来源（真实系统） |
|---|---|
| 项目目标环 / 门禁标签 | goal{attain, gate, eval_way, due, status} |
| 任务行 / 达成度 / 拆解徽章 | task{level≤5, pct, decomp_flag(首子任务=拆解), subs} |
| 契约/预测漂移 chip | task{contract_due, predicted_due} |
| 里程碑集合 chip / 轨道 | milestone{task_refs[], due} → 四态推导 |
| 四类风险 chips / 严重度章 | risk{cat∈四类, p, i, owner, status} |
| 阶段变化 chips / 窗口 KPI | events.jsonl 按窗口过滤聚合 |
| 12 周热力 / sparkline | events 按周桶聚合 |

## 5. 落地施工建议（viewer/template.html + schema v0.2）

1. **导航**：`viewNav` 增加「风险」为一级视图（`#v-risk`），与结构/时间线/统计并列。
2. **聚合层**：`store` 滚动汇总增加按节点×周的事件桶、风险四类计数、目标/任务/里程碑聚合（GET /api/snapshot 扩展，或新增 `/api/riskview`）。
3. **schema v0.2 增量**（待拍板后启动）：
   - `goal`：{id, owner_node, name, gate, eval_way, due, attain, status}
   - `task`：{id, parent, level(≤5), contract_due, predicted_due, pct, decomp_task_id}
   - `milestone`：由"日期+状态"改为 `{task_refs[], due}`，四态改推导
   - `risk`：增加 `cat`(四类)、`task_ref`
   - 事件类型枚举扩展：`risk.open/risk.close/task.move/gate/ms.slip/decomp/fte`
4. **变体落地顺序建议**：A 为默认；B 的矩阵作为统计页新卡；C 的时间泳道与现有"时间线"页合并演进（共用今天线/里程碑轨道组件）。
5. **组件复用**：主题 token、状态点、Peek 壳、⌘K 全部沿用现有实现。
