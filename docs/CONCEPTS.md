## 0. 目标与目标管理

- **可实现**：目标必须挂实现期限契约（FTE 契约管理）。
- **可量化评估**：每个目标配**评价体系/工具/指标**，并设置量化**准入门槛（门禁）**；"完成"不是 100% 打折完成，而是通过门禁评价（实现程度、质量/稳定性）。
- **需要风险管控**：进度 / 质量 / 资源（人力/物力；参与含 Agent 的有效投入时间）。

## 1. 项目与项目目标

- 项目 = 为"在一段时间内稳定提供某种能力"而展开的活动的集合；**项目是超大任务**。
- **项目目标** = 项目需实现的关键能力/指标集合；关注"达到什么效果"，不预设实现方式。
- 目标拆解质量决定实现质量上限 → **项目目标的首个子任务 = 目标拆解任务**（拆解本身是被跟踪的任务）。

## 2. 任务 / 任务目标 / 拆解

- 任务目标 = 体现任务完成的关键指标集合，同样走目标管理过程；任务越小，任务目标越接近任务本身。
- 层级：项目目标 → 一级任务 → 二级任务 → …（建议 ≤5 级）。
- **每个父任务的第一个子任务 = 该任务的拆解任务**（是否已拆解是被跟踪状态；未拆解本身即管理风险信号）。
- 拆解反映对目标的理解、实现路径、可并发性（影响资源调度与协作成本）。

## 3. 里程碑

- 从一级任务（或二级任务）中挑选的**任务集合**；**集合内全部任务达成 = 里程碑达成**。
- 状态推导：全部达成=hit；过契约未达成=missed；任一成员任务预测滑过契约=at-risk；其余=planned。

## 4. 风险（四类）

> 定义：任何导致任务/项目无法在有限时间、匹配合适资源、通过评价门禁的因素。

| 类别 | 含义 | 视觉约定（原型） |
|---|---|---|
| **进度风险** | 推进速度不达预期，可预见完成时间晚于契约时间 | 琥珀 `--cat-prog` |
| **资源风险** | 刚需资源缺口（缺人/缺硬件/缺账号等） | 紫 `--cat-res` |
| **关键问题风险** | 关键问题无解决方案（技术能力缺口，甚至业界无解） | 红 `--cat-prob`（最高警示级） |
| **质量风险** | 已初步实现但过不了评价门禁 | 蓝 `--cat-qual` |

## 5. Event 与阶段性汇报

- Event = 可跟踪的原子事件或其**集合**（集合化服务于高层视角的清晰表达）。
- 事件类型（原型）：`risk.open / risk.close / task.move / gate(门禁过/挂) / ms.slip / decomp(拆解产出) / fte(资源投入变化)`。
- **宏观视图必须体现一段时间内（时间段可输入）的事件状态变化**——阶段汇报窗口是全局控件（7/14/30/90 天或自定义），驱动：KPI"窗口内事件"、每项目"阶段变化 chips"（+登记 −解除 · 迁移 · 滑动 · 门禁 ✓/✗ · 拆解 · FTE）、窗口列高亮、下钻事件流。

## 6. 与旧模型的映射（v0.1 → 概念 v2）

| v0.1（现实现） | 概念 v2 |
|---|---|
| project/module/feature/interface | 项目（超大任务）→ 任务的层级拆解（一级…N 级，≤5）；module/feature 可视为任务层级的历史命名 |
| design/impl 双轴状态 | 保留：可作为任务目标达成过程的两轴证据；"设计先行/证据缺口"即四类风险之外的过程风险信号 |
| milestone（日期+四态） | 里程碑 = 任务集合（达成=集合内全员达成），四态保留但改为推导值 |
| 风险（概率×影响） | 保留 p×i 暴露值，**增加类别维度（四类）** |
| events.jsonl 只追加 | 保留，即"阶段性汇报窗口"的数据源 |
